Module 1 — Fondamentaux et premières automatisations

Leçon 04 — Automatiser les formulaires, les emails et les notifications

  • Niveau : Débutant
  • ⏱ 30 min
  • 5 parties

Objectif : créer des automatisations simples qui collectent des informations via un formulaire et préviennent automatiquement les personnes concernées par e-mail et messagerie instantanée.

Dans cette leçon

  1. Anatomie de la collecte d'information
  2. Configurer le déclencheur
  3. Rédiger des e-mails automatiques
  4. Envoyer des notifications d'équipe
  5. Tester et gérer les erreurs

1.Anatomie de la collecte d'information

Une automatisation n'est fiable que si les données qui y entrent sont propres. Tout commence donc par le formulaire.

Les règles d'un bon formulaire

  • Un champ, une information : séparez Prénom et Nom plutôt qu'un seul champ « Nom complet ». Vous pourrez ainsi écrire « Bonjour Camille ».
  • Peu de champs obligatoires : exigez seulement ce dont l'automatisation a besoin pour fonctionner (au minimum, l'adresse e-mail).
  • Des réponses prévisibles : préférez une liste déroulante à un texte libre quand les choix sont connus.
  • Une validation à la source : activez la vérification du format (e-mail, téléphone, date).

Texte courtPrénom, nom, sociétéVariable simple à insérer dans un message
E-mailAdresse de contactFormat vérifié, évite les erreurs d'envoi

💡

Astuce. Après la Leçon 02, gardez en tête votre tâche à automatiser et demandez-vous : de quelles informations le traitement a-t-il vraiment besoin ? Tout champ en plus est un frein pour la personne qui remplit.

2.Configurer le déclencheur

Le déclencheur est l'événement qui lance le scénario : ici, l'envoi du formulaire. Deux approches existent.

  • Le déclencheur « nouvelle réponse » proposé par l'orchestrateur pour votre outil de formulaire. C'est le plus simple à configurer.
  • Le webhook (vu à la Leçon 03) : le formulaire envoie lui-même les données à l'adresse fournie par l'orchestrateur, dès l'envoi.
⚠️

Attention au délai. Selon l'outil et l'offre choisis, un déclencheur peut vérifier les nouvelles réponses à intervalles réguliers plutôt qu'instantanément. Vérifiez cette information dans la documentation de l'outil.

🔗

Pour tester le déclencheur. Envoyez une réponse de test au formulaire : l'orchestrateur affiche alors les champs reçus, que vous réutiliserez comme variables dans les étapes suivantes.

3.Rédiger des e-mails automatiques

Un e-mail automatique doit être aussi soigné qu'un message écrit à la main. Les variables dynamiques insèrent les réponses du formulaire dans le texte : {{prenom}}, {{demande}}, etc.

Structure d'un accusé de réception professionnel

  1. Objet clair : il dit tout de suite de quoi il s'agit.
  2. Salutation personnalisée avec le prénom.
  3. Confirmation que la demande est bien reçue.
  4. Récapitulatif de ce qui a été envoyé.
  5. Prochaine étape et délai : que va-t-il se passer ?
  6. Signature et contact, avec une vraie personne à joindre.

Aperçu en direct

Objet : nous avons bien reçu votre demande

Bonjour ,

Merci pour votre message. Nous confirmons la réception de votre demande : .

Un membre de l'équipe vous répondra sous .

Cordialement,
L'équipe Exemple
contact@exemple.fr

⚠️

Prévoyez les champs vides. Si le prénom manque, le message « Bonjour , » fait mauvais effet. Remplacez la variable par une valeur de secours (« Bonjour, ») grâce à la fonction « si vide » de votre outil. Essayez-le dans l'aperçu en effaçant le prénom.

4.Envoyer des notifications d'équipe

L'e-mail s'adresse au client. L'équipe, elle, a besoin d'être prévenue vite, là où elle travaille déjà : Slack, Discord ou Microsoft Teams. Les trois peuvent recevoir des messages d'un orchestrateur, via un connecteur ou une adresse de webhook que vous créez dans le canal.

Un bon message d'équipe est court

  • Qui a fait la demande.
  • Quoi : le type de demande en une phrase.
  • Urgence si elle existe.
  • Un lien vers la ligne du tableau ou le dossier complet.

Router selon le type de demande

Un « routeur » ou « filtre » envoie le message vers le bon canal selon la valeur d'un champ. Choisissez un type pour voir le résultat.

5.Tester et gérer les erreurs

Un scénario qui marche une fois ne marche pas forcément toujours. Testez avec des cas normaux, puis avec des cas qui posent problème. Cliquez sur une situation pour voir comment réagir.

Cause : un champ facultatif est vide ou un champ a été renommé dans le formulaire.

Que faire : rendez le champ obligatoire s'il est indispensable, ou prévoyez une valeur de secours. Après toute modification du formulaire, relancez un test pour actualiser les champs reçus.

Cause : faute de frappe, espace en trop, adresse inexistante.

Que faire : activez la validation du champ e-mail dans le formulaire. Ajoutez une branche « en cas d'erreur » qui prévient l'équipe pour qu'elle contacte la personne autrement.

À vérifier dans l'ordre : le scénario est-il activé ? L'adresse du webhook est-elle bien collée dans le formulaire ? Le formulaire est-il publié ? L'historique d'exécution de l'orchestrateur affiche-t-il une tentative ?

Cause : l'autorisation a expiré, un mot de passe a changé ou une clé d'API a été supprimée.

Que faire : reconnectez le compte dans l'orchestrateur, puis relancez l'exécution qui a échoué depuis l'historique.

⚠️

Ne testez pas sur de vrais clients. Utilisez vos propres adresses et un canal d'équipe de test, pour éviter d'envoyer des messages par erreur.

Liste de test avant la mise en route

0 test sur 5 validé

  • Toutes les informations sont renseignées : l'e-mail et le message d'équipe arrivent correctement.
  • Le message reste lisible, sans variable vide.
  • Le formulaire la refuse, ou l'alerte d'erreur prévient l'équipe.
  • Chaque valeur de la liste déroulante arrive dans le bon canal.
  • L'e-mail reçu reste clair sur un téléphone.

À retenir

  • Un formulaire propre rend l'automatisation fiable : peu de champs obligatoires, des types adaptés.
  • Le déclencheur capte chaque réponse ; vérifiez s'il agit en temps réel.
  • Un accusé de réception clair confirme, récapitule et annonce la suite.
  • Les messages d'équipe sont courts et routés vers le bon canal.
  • Testez les cas qui posent problème et prévoyez une alerte d'erreur.
