01

Le rôle des protocoles

Un protocole définit comment les équipements échangent des informations.

Dans un réseau, plusieurs services coopèrent. Le DNS associe un nom à une adresse IP, le DHCP fournit automatiquement des paramètres réseau et HTTP/HTTPS transporte les échanges liés au Web.

Figure 1 — Plusieurs services coopèrent pour permettre une communication applicative.
💡 À retenirDNS répond à « quel est le nom/adresse ? », DHCP à « quels paramètres réseau utiliser ? », et HTTP/HTTPS à « comment échanger avec un service Web ? ».
02

DNS — résoudre les noms

Le Domain Name System transforme les noms de domaine en informations exploitables par le réseau.

Un utilisateur saisit généralement un nom comme www.exemple.tld. Le DNS permet de retrouver l'adresse IP associée afin que le client puisse communiquer avec le serveur.

Figure 2 — Vue simplifiée d'une résolution de nom.

03

DHCP — attribuer les paramètres réseau

Le Dynamic Host Configuration Protocol automatise une partie de la configuration IP des clients.

Un serveur DHCP peut fournir notamment une adresse IP, un masque de sous-réseau, une passerelle par défaut et des serveurs DNS. Cela évite de configurer manuellement chaque poste.

Figure 3 — Séquence DORA : Discover, Offer, Request, Acknowledge.
①

②

Offer

Le serveur propose une configuration.

③

Request

Le client demande la configuration proposée.

④

Le serveur confirme l'attribution.

04

HTTP et HTTPS

Les protocoles Web transportent les échanges entre un client et un serveur applicatif.

HTTP utilise généralement le port 80. Il sert au transport des échanges Web sans le chiffrement apporté par TLS.
HTTPS utilise généralement le port 443 et ajoute TLS pour protéger la communication entre client et serveur.
Figure 4 — Schéma conceptuel d'une requête Web et de sa réponse.
🔒 Sécurité / bonne pratiquePour les services Web, HTTPS est le choix habituel lorsqu'une protection de la communication est nécessaire. Le certificat et la configuration TLS doivent également être surveillés.

07

Outils de diagnostic

Les commandes réseau permettent de vérifier chaque maillon séparément.

Résolution

nslookup permet d'interroger un serveur DNS et d'observer la résolution d'un nom.

Configuration IP

ipconfig permet d'observer les paramètres réseau d'un poste Windows.

Connectivité

ping aide à vérifier si une cible répond au niveau IP.

Chemin réseau

tracert permet d'observer le chemin suivi vers une destination.

CONSOLE · WINDOWS
ipconfig /all
CONSOLE · DIAGNOSTIC DNS
nslookup www.exemple.tld
🔗 Pour aller plus loinPour diagnostiquer méthodiquement, isoler les couches : configuration locale → connectivité IP → résolution DNS → accès au service applicatif.
Pourquoi tester dans cet ordre ?

Parce qu'un problème situé en amont peut rendre les tests suivants trompeurs. Vérifier progressivement la configuration, l'adressage, la résolution puis l'application réduit l'espace de recherche.

08

Points clés à retenir

Les quatre repères essentiels de la leçon.

DNS

Associe les noms aux informations d'adressage nécessaires à la communication.

DHCP

Automatise l'attribution de paramètres réseau aux clients.

HTTP(S)

Permet les échanges Web, avec HTTPS et TLS pour une communication protégée.

Ports

53, 67/68, 80 et 443 sont des repères importants pour ces services.

Diagnostic

Tester séparément configuration, connectivité, DNS et application.

Méthode

Comprendre le rôle de chaque service avant de modifier une configuration.
