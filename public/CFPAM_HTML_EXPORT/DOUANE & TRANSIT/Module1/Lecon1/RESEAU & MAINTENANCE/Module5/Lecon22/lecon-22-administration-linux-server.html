Administration Linux Server

Administrer un serveur Linux en ligne de commande.

💡 À retenirLe terminal est le point central de l'administration Linux : on observe le système, on modifie sa configuration et on contrôle ses services avec méthode.
NiveauAvancé
Durée15 min
ThèmesLigne de commande · paquets · permissions · systemd · journaux
01 / TERMINAL

Ligne de commande

La ligne de commande permet de piloter un serveur sans interface graphique. Elle sert à naviguer dans l'arborescence, inspecter l'état du système et lancer des opérations d'administration.

⌁

Naviguer

pwd, ls et cd permettent de se repérer et de parcourir les répertoires.

▤

Observer

ps, df, free et uname donnent une vue de l'état du serveur.

›_

Administrer

sudo permet d'exécuter certaines opérations avec les privilèges nécessaires.

SESSION SHELL 
pwd
ls -lah
cd /var/log
whoami
uname -a
02 / LOGICIELS

Gestion des paquets

Les gestionnaires de paquets installent, mettent à jour et suppriment les logiciels tout en gérant leurs dépendances.

Avec apt :

APT 
sudo apt update
sudo apt upgrade
sudo apt install nginx
sudo apt remove nginx

Avec dnf :

DNF 
sudo dnf check-update
sudo dnf upgrade
sudo dnf install nginx
sudo dnf remove nginx
03 / ACCÈS

Permissions

Les permissions Linux définissent les droits de lecture, écriture et exécution pour le propriétaire, le groupe et les autres utilisateurs.

SymboleDroitValeurExemple
rLecture4chmod 640 fichier
wÉcriture2chmod u+w fichier
xExécution1chmod +x script.sh
INSPECTER 
ls -l /etc/hosts
id
stat fichier.txt
MODIFIER 
chmod 640 fichier.txt
chown admin:admin fichier.txt
chgrp support fichier.txt
🔒 Sécurité / bonne pratiqueAppliquer le principe du moindre privilège : attribuer uniquement les droits nécessaires.

05 / DIAGNOSTIC

Journaux

Les journaux servent à comprendre les événements du serveur : démarrage, services, authentification et erreurs.

⌁

journalctl

Interroger les journaux et les filtrer par service ou période.

▥

/var/log

De nombreux journaux système sont également présents dans cette arborescence.

DIAGNOSTIC 
journalctl
journalctl -u nginx
journalctl -b
journalctl --since "1 hour ago"
tail -f /var/log/syslog
Pourquoi filtrer les journaux ?

Le volume d'événements peut être important. Un filtre par service ou période réduit le bruit et facilite le diagnostic.

Quelle méthode adopter ?

Partir du symptôme, vérifier l'état du service, consulter les événements associés, formuler une hypothèse puis vérifier le résultat.

🛠️ Méthode de diagnosticPour un service qui ne répond plus : systemctl status → journalctl -u → contrôle de la configuration et des ressources.
