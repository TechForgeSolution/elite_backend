01 · Vue d'ensemble

Administrer un serveur en ligne de commande

Un serveur Linux s'administre le plus souvent à distance via SSH, sans interface graphique. L'administrateur agit avec des commandes : installer, configurer, sécuriser, surveiller.

CLI

Commander

Le shell exécute les commandes tapées par l'administrateur.

PKG

Installer

Le gestionnaire de paquets ajoute et met à jour les logiciels.

SVC

Superviser

systemd pilote les services et les journaux les tracent.

02 · Ligne de commande

Se déplacer et agir dans le shell

Une commande suit la forme commande [options] [arguments]. Les droits d'administration s'obtiennent ponctuellement avec sudo, plutôt qu'en travaillant en root.

CommandeRôle
pwd · ls -la · cdSe repérer, lister, changer de dossier
cp · mv · rmCopier, déplacer, supprimer
cat · less · grepLire et rechercher dans des fichiers
nano /etc/hostsÉditer un fichier de configuration
man commandeConsulter le manuel
# Se connecter au serveur
ssh admin@192.168.10.5
# Chercher les erreurs dans un fichier
grep -i "error" /var/log/syslog | tail -n 20
⚠️ Attention / erreur fréquenterm -rf supprime sans confirmation ni corbeille. Vérifiez toujours le chemin avant de valider, surtout avec sudo.
03 · Gestion des paquets

Installer et mettre à jour

Un paquet regroupe un logiciel, ses fichiers et ses dépendances. Le gestionnaire de paquets les télécharge depuis des dépôts officiels et gère les mises à jour.

sudo apt update
sudo apt install nginx
sudo apt upgrade
sudo apt remove nginx
sudo dnf check-update
sudo dnf install nginx
sudo dnf upgrade
sudo dnf remove nginx
💡 À retenirSur Debian/Ubuntu, faites apt update (actualiser la liste des paquets) avant apt install.
04 · Permissions

Propriétaires, groupes et droits

Chaque fichier a un propriétaire, un groupe et des droits pour trois catégories : propriétaire, groupe, autres. Chaque droit vaut un chiffre : lecture 4, écriture 2, exécution 1.

ls -l script.sh          # -rwxr-x--- 1 admin devs ...
chmod 750 script.sh       # rwx r-x ---
chmod u+x,g-w script.sh   # notation symbolique
chown admin:devs script.sh
⚠️ Attention / erreur fréquentechmod 777 ouvre tous les droits à tout le monde : c'est presque toujours une mauvaise solution. Appliquez le moindre privilège.
05 · Services systemd

Piloter les services

systemd démarre le système et gère les services (unités). La commande systemctl permet de les lancer, les arrêter et de contrôler leur démarrage automatique.

01
status : lire l'état
02
start / stop : agir maintenant
03
enable : au démarrage
04
restart : recharger la config
sudo systemctl status nginx
sudo systemctl restart nginx
sudo systemctl enable --now nginx
systemctl list-units --type=service --state=failed
Quelle différence entre start et enable ?

start lance le service maintenant ; enable le lance à chaque démarrage. Les deux sont indépendants, sauf avec enable --now.

Quelle différence entre restart et reload ?

restart arrête puis relance le service (coupure brève) ; reload recharge la configuration sans l'arrêter, si le service le permet.

06 · Journaux

Lire les journaux

Les journaux racontent ce qui s'est passé : démarrages, erreurs, connexions. Ils sont collectés par journald (commande journalctl) et stockés en partie dans /var/log.

journalctl -u nginx -n 50        # 50 dernières lignes du service
journalctl -p err --since today  # erreurs du jour
journalctl -f                 # suivre en direct
tail -f /var/log/auth.log     # tentatives de connexion
💡 À retenirDevant un service en panne : systemctl status puis journalctl -u. La cause est presque toujours dans les dernières lignes.

08 · Synthèse

Points clés à retenir

Administrer un serveur Linux consiste à agir prudemment, avec les bons outils, et à vérifier les journaux.

Shell — sudo ponctuel, prudence avec rm.
Paquets — apt ou dnf selon la distribution.
Permissions — r=4, w=2, x=1 ; moindre privilège.
systemd — systemctl start / enable / status.
Journaux — journalctl -u et /var/log.
Méthode — état, journal, correction, vérification.
💡 À retenirUn bon administrateur installe le nécessaire, limite les droits, contrôle les services et lit les journaux avant de corriger.
