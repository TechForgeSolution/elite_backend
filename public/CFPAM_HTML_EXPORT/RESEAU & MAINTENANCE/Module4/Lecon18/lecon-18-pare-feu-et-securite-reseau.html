Pare-feu et sécurité réseau

Configurer des règles de filtrage adaptées à un scénario d'entreprise.

01 · Vue d'ensemble

Le rôle d'un pare-feu

Un pare-feu (firewall) contrôle les flux entre deux réseaux de niveaux de confiance différents. Il compare chaque paquet à une politique de sécurité, puis l'autorise ou le bloque.

FLT

Filtrer

Autorise ou refuse selon adresses, ports et protocoles.

SEG

Segmenter

Sépare Internet, DMZ et réseau interne.

LOG

Tracer

Conserve la trace des flux autorisés et bloqués.

02 · Règles de filtrage

Écrire des règles de filtrage

Une règle associe des critères (source, destination, protocole, port) à une action. Le pare-feu lit les règles dans l'ordre et applique la première qui correspond. Sans correspondance, la politique par défaut s'applique.

CritèreExempleAction
Source192.168.10.0/24ACCEPT / DROP / REJECT
Destination172.16.0.10
ProtocoleTCP, UDP, ICMP
Port80, 443, 22
💡 À retenirPolitique recommandée : tout refuser par défaut, puis n'autoriser que les flux nécessaires (principe du moindre privilège).
⚠️ Attention / erreur fréquenteUne règle « tout autoriser » placée trop haut rend inutiles toutes les règles situées en dessous.
03 · Zone démilitarisée

La DMZ

Une DMZ est un réseau intermédiaire qui héberge les serveurs accessibles depuis Internet (web, messagerie, DNS public). Si un de ces serveurs est compromis, l'attaquant reste isolé du LAN.

04 · NAT

Traduction d'adresses (NAT)

Le NAT modifie les adresses IP des paquets qui traversent le routeur ou le pare-feu. Il permet à des adresses privées d'accéder à Internet et de publier un service interne.

Traduit l'adresse source : tout le LAN sort avec une seule adresse publique, différenciée par les ports.

Traduit l'adresse destination : le trafic arrivant sur l'IP publique est redirigé vers un serveur (redirection de port).

# SNAT / masquerade : le LAN sort avec l'IP publique
iptables -t nat -A POSTROUTING -s 192.168.10.0/24 -o eth0 -j MASQUERADE
# DNAT : redirection du port 443 vers la DMZ
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 443 -j DNAT --to-destination 172.16.0.10
⚠️ Attention / erreur fréquenteLe NAT n'est pas un pare-feu : il masque les adresses, mais ne remplace pas les règles de filtrage.
05 · Listes de contrôle d'accès

ACL et exemple de politique

Une ACL est une liste ordonnée de règles permit / deny appliquée à une interface, dans un sens (entrant ou sortant).

Politique d'entreprise : LAN 192.168.10.0/24, DMZ 172.16.0.0/24.

# Politique par défaut : tout refuser
iptables -P FORWARD DROP
# LAN → Internet : web uniquement
iptables -A FORWARD -s 192.168.10.0/24 -p tcp -m multiport --dports 80,443 -j ACCEPT
# Réponses des connexions établies
iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT
# Internet → serveur web en DMZ
iptables -A FORWARD -d 172.16.0.10 -p tcp --dport 443 -j ACCEPT
# Journaliser puis refuser le reste
iptables -A FORWARD -j LOG --log-prefix "FW-DROP: "
ip access-list extended INTERNET-IN
 permit tcp any host 172.16.0.10 eq 443
 permit tcp any any established
 deny ip any 192.168.10.0 0.0.0.255 log
 deny ip any any log
interface GigabitEthernet0/0
 ip access-group INTERNET-IN in
💡 À retenirUne ACL se termine par un deny implicite : ce qui n'est pas explicitement autorisé est refusé. Placer les règles les plus précises en premier.
06 · Journalisation

Journaliser et analyser

La journalisation enregistre les décisions du pare-feu : elle sert à détecter des tentatives d'intrusion, diagnostiquer une règle et prouver la conformité.

Que faut-il journaliser ?

Les refus (surtout ceux venant d'Internet), les accès administrateur, les modifications de règles et les connexions vers les zones sensibles.

Que contient une entrée de journal ?

Date et heure, adresses source et destination, ports, protocole, action (accepté ou refusé) et règle appliquée.

Comment éviter la saturation ?

Ne pas tout journaliser, centraliser les logs sur un serveur dédié et définir une durée de rétention.

08 · Synthèse

Points clés à retenir

Un pare-feu applique une politique cohérente, ordonnée et tracée.

Règles — lues dans l'ordre, politique par défaut : refuser.
DMZ — isole les serveurs publics du LAN.
NAT — traduit les adresses, ne remplace pas le filtrage.
ACL — permit/deny par interface et par sens.
Journaux — détection, diagnostic, preuve.
Moindre privilège — n'ouvrir que le nécessaire.
💡 À retenirConfigurer un pare-feu d'entreprise : segmenter, autoriser le strict nécessaire, traduire les adresses si besoin, puis journaliser.
